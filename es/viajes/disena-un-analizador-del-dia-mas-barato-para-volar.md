Contexto: Estoy diseñando [tipo de producto] (app, bot o función dentro de un sitio de viajes) que recomienda los días más baratos para volar en una ruta y un rango de fechas que elige el usuario. Mi equipo trabaja con [stack o herramientas disponibles] y el público es [público objetivo].
Objetivo: Tener una especificación clara para construir un primer prototipo que dé recomendaciones útiles y honestas sobre en qué fechas volar y cuándo comprar.
Entregable: 1) Fuentes de datos posibles (APIs de tarifas y proveedores de datos históricos), con los datos que entrega cada una, su costo y sus restricciones de uso. 2) Metodología de análisis: estacionalidad, día de la semana, anticipación de compra, eventos y demanda, y el modelo o la heurística que conviene para un prototipo. 3) Cómo se muestra el resultado: calendario de precios, nivel de confianza y explicación breve. 4) Métricas para evaluar si las predicciones aciertan. 5) Riesgos y limitaciones.
Criterios: El acceso a APIs de vuelos cambia seguido; usa búsqueda web si la tienes para confirmar qué servicios están disponibles hoy y bajo qué condiciones, y marca como estimación lo que no puedas confirmar. Prefiere una solución simple que funcione a una compleja difícil de mantener. Comunica cada predicción como probabilidad, nunca como garantía de precio.
Formato: Documento con las 5 secciones numeradas, viñetas y una tabla para las fuentes de datos. Entre 800 y 1,200 palabras.
