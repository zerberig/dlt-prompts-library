Context: I'm designing [tool name], an AI tool for content creators that solves this problem: [problem it solves]. The primary user is [target user]. Constraints: [budget, team, and timeline].
Goal: A clear requirements document my design and engineering team can use to estimate and build the first version.
Deliverable:
1) Problem and value proposition in 3–4 sentences, including the alternatives users rely on today.
2) 2 user profiles with their main jobs to be done.
3) Prioritized features (must-have, nice-to-have, later), noting where AI adds real value and where a conventional feature is enough.
4) MVP scope and what's out of scope, with the reason.
5) Licensing, usage-rights, and privacy requirements for the content the tool handles.
6) Success metrics and key risks with mitigations.
Criteria: Every feature must map to a user task; if it doesn't, drop it. Write testable requirements (what should happen and how to verify it). If you have web search, review current competitors and flag any market data as an estimate.
Format: A document with numbered headings; features in a table with the columns Feature, User task, Priority, Acceptance criterion.
If any essential information is missing, ask me up to 3 questions before you start.
