Context: I'm designing a tool that helps [target audience] find cheaper itineraries by combining one-way flights across different airlines or airports, instead of booking a traditional round trip or multi-city ticket. The first version will launch as [launch platform].
Goal: A product requirements document (PRD) that design and engineering can use to build an MVP.
Deliverable: 1) Product overview: problem, value proposition, target user, and 3 to 5 key features. 2) Functional requirements: search and ranking logic (price, duration, stops), itinerary builder, price alerts, and baggage guidance. 3) User risks and how to mitigate them: missed connections on separate tickets, minimum connection times, re-checking bags, transit and visa requirements. 4) Data sources and their usage restrictions. 5) User experience: search flow and how risks are communicated. 6) Success metrics and MVP scope vs. future versions.
Criteria: Transparency about self-transfer risks is central to the product, because a user who misses a connection loses trust. Respect airline and data provider terms of service; use web search if you have it to confirm which APIs are available today, and mark anything you can't confirm.
Format: A document with the 6 numbered sections, bullets, and a requirements table with the columns Requirement, Priority, and Acceptance criterion. 900 to 1,400 words.
If any essential information is missing, ask me up to 3 questions before you start.
