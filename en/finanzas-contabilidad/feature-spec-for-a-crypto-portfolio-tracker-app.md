Context: We're building [app name], an app for tracking cryptocurrency portfolios, aimed at [target users] (beginners, active investors, or both). It will launch on [launch platforms], and the business model is [business model].
Goal: I want a feature document the development team can estimate and build in phases, balancing ease of use for beginners with depth for advanced users.
Deliverable: 1) A feature list prioritized with MoSCoW (must, should, could, won't for now): read-only exchange and wallet connections, manual entry, real-time prices, performance and average cost, alerts, tax reports, news, beginner mode. 2) For each "must" feature: description, acceptance criteria, and technical dependencies. 3) Security and privacy requirements: API key handling, authentication, encryption, and data we should never store. 4) Required data integrations and the risks of each provider. 5) A 3-phase plan with the scope of each phase.
Criteria: Prioritize by user value and technical risk, and justify each decision. Connections must be read-only, and the app should tell users so, because security is the main trust barrier in crypto. Avoid features that read as investment advice.
Format: A MoSCoW table with the columns Feature, Priority, User value, and Estimated effort; sections for security and integrations; the phased plan as a table.
If any essential information is missing, ask me up to 3 questions before you start.
