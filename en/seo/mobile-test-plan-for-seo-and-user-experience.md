Context: My site [your site name or URL] is for [site purpose] (store, lead generation, content, etc.), and most of my visitors arrive on their phones.
Goal: I want to find the mobile issues that hurt rankings and conversions, because search engines index the mobile version first.
Deliverable: A test plan covering navigation and menus, content readability, forms and keyboard behavior, buttons and calls to action, speed and Core Web Vitals, basic accessibility, and content parity between mobile and desktop. For each area: what to check, how to test it (with free tools such as Lighthouse, PageSpeed Insights, or the Search Console report), and what counts as a pass.
Criteria: Tests someone without a developer background can run, with clear steps. Include a short list of representative screen sizes and operating systems rather than specific phone models, since those change every year. If you cite metric thresholds, verify them with web search if you have it.
Format: A table with the columns Area, What to check, How to test, Pass criterion, and Priority (high, medium, low).
If any essential information is missing, ask me up to 3 questions before you start.
